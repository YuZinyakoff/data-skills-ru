# Применение Data Skills RU

Используй установленный пакет `data_skills_ru` или его исходный репозиторий.
В начале уточни фактическое расположение пакета и входного файла;
не подставляй вымышленный адрес GitHub. Если пакет недоступен, сообщи
об этом и подготовь установку из предоставленного пользователем источника.

## Вход и запуск

Подготовь UTF-8 JSONL, CSV или Parquet с уникальным строковым `identifier`.
Текстовые поля: `title`, `requirements_qualifications`, `responsibilities`.
Отсутствующее поле допустимо. Присутствующие null/числа требуют
явной подготовки; не превращай неизвестное содержание в придуманный текст.
Для JSONL/CSV и Python API достаточно обычной установки; Parquet требует
необязательного дополнения `.[parquet]`.

```bash
python -m data_skills_ru --input vacancies.jsonl --out-dir results-run-01 --evidence
```

Каталог результатов должен быть новым. Проверь успешный код завершения
и `completed.json` со статусом `complete`. При ошибке сохрани её
диагностику; частичные CSV без подтверждения завершения результатом
готового прогона не являются.

## Интерпретация

- A: ИИ/ML; B: специальные количественные методы; C: аналитика/статистика; D: техническая работа с данными; E: общий ИТ; F: промышленная автоматизация.
- AD является объединением A–D. E рассчитывается отдельно, F в AD не входит.
- Для долей считай объявления по `flags.csv`, указывая знаменатель.
- В `evidence.csv` учитывай `accepted`: файл содержит и отклонённые упоминания.
- Позиции цитат относятся к тексту в нижнем регистре; `end` не включается.
- Нулевая метка означает отсутствие принятого словарного основания при этих входах. Ошибки и пропуски возможны.

При разборе спорного ответа прочитай README и `docs/METHOD_RU.md`
в исходном репозитории; для количественных метрик `docs/QUALITY_RU.md`.
Сохраняй версию, хеш словаря и число обработанных объявлений в отчёте.

Не заменяй результаты программы собственными семантическими догадками.
Отдельное предложение изменить метку сохраняй как авторскую проверку,
не смешивая его с исходным ответом классификатора. Штатный словарь
меняй только в явно запрошенной работе над новой версией; её качество
нужно оценивать отдельно. Исходные тексты не отправляй во внешние
сервисы без соответствующего запроса пользователя.
